# 0001 体验丝滑优先，滥用靠侦测与处置兜底

日期：2026-09-18 · Sprint 11

## 背景
Sprint 11 要把「网站 → 微信群 → 回到网站」这条路做顺：一键长图、扫码进卖家摊位、搜索栏里直接提问和反馈。每一处顺滑都同时是一个可被批量利用的口子（按卖家归集物品、批量查看联系方式、刷反馈）。设计过程中 AI 两次倾向于「先加限制」——给物品配手打短编号、禁止按联系方式搜索——都被否决：前者体验差，后者限制的是线上早已存在的能力。

## 决定
1. 正常用户的操作做到极致顺滑，工程为体验服务；不为假想的滥用预先牺牲体验。
2. 滥用用**埋点侦测 + 分级响应**兜底：轻 → 后台面板与每日摘要；重 → 立即发邮件，并自动暂停该访客查看联系方式 24 小时（后台可解除）。
3. 自动处置只作用于最窄的动作（查看联系方式）和最窄的主体（单个访客）。不封 IP：校园 NAT 下一个 IP 背后是很多真人。
4. 方案由 AI 建议，取舍由人感受后拍板；规格里每一条标注来源（人说的 / AI 建议 / AI 猜测 / 代码事实），让猜测可以被一眼否决。

## 后果
- 阈值（10 / 30 / 8）是猜的，要按真实告警调；误伤的代价是一位真实买家 24 小时内看不了联系方式，靠后台「解除」补救。
- 侦测依赖 9A 的配额流水 `RateLimitHit`，没有新表；流水 48 小时回收，所以只能看近两天。
- 个人信息仍不进 URL（摊位用不透明短码）、服务端取图只认 Cloudinary——这两条是安全底线，不属于「为体验让路」的范围。
